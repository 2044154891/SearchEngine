# CppJieba 分词与大语言模型 Token/向量 对比说明

## 1. 这份说明讲什么

本文面向当前 `Search_Engine` 项目，解释：

1. 项目里 CppJieba 是怎么被使用的
2. CppJieba 分词底层算法步骤（便于理解原理）
3. 传统搜索里的“词项（term）/权重”与大模型里的“token/向量”是什么关系
4. 两种技术路线在工程目标上的差异与互补方式

---

## 2. 当前项目中 CppJieba 的实际用法

从代码看，CppJieba 被封装在 `SplitToolCppJieba` 中，作为统一分词入口：

- 单例初始化位置：`src/SplitToolCppJieba.cc`
- 对外接口定义：`include/SplitToolCppJieba.h`

### 2.1 初始化做了什么

`SplitToolCppJieba` 初始化时会加载以下资源：

- 主词典：`jieba.dict.utf8`
- HMM 模型：`hmm_model.utf8`
- 用户词典：`user.dict.utf8`
- IDF：`idf.utf8`
- 停用词：`stop_words.utf8`

这些文件位于项目 `include/cppjieba/dict/` 目录中。

### 2.2 离线阶段怎么用（建索引）

在 `src/PageLibPreprocessor.cc` 中，流程是：

1. 读取网页文档（标题 + 正文）
2. 调用 CppJieba 分词
3. 去停用词
4. 统计词频（TF）
5. 统计文档频率（DF）
6. 计算 TF-IDF
7. 做 L2 归一化
8. 写入倒排索引

这意味着：
- CppJieba 负责“把文本切成可检索词项”
- PageLibPreprocessor 负责“把词项变成检索权重结构”

### 2.3 在线阶段怎么用（查索引）

在 `src/WebPageSearcher.cc` 中：

1. 对用户查询先分词（`cutQuery`）
2. 用分词结果去查倒排索引
3. 累加文档得分并排序
4. 返回 Top-K 结果

所以在线时 CppJieba 主要用于“查询解析（query parsing）”。

## 3. CppJieba 分词底层算法步骤（核心原理）

可以把 CppJieba 理解为“词典驱动 + 概率解码 + 新词兜底”的组合。

### 3.1 词典与模型准备

根据项目中的初始化和 `include/cppjieba/dict/README.md`：

- `jieba.dict.utf8`：用于最大概率分词（MPSegment）
- `hmm_model.utf8`：用于 HMM 分词（HMMSegment）
- 混合模式（MixSegment）会同时使用两者

### 3.2 构建前缀结构（Trie 思想）

把词典组织成前缀可检索结构，快速回答：

- 从当前位置开始，哪些子串是可能词
- 哪些是完整词，哪些只是前缀

这样能高效枚举候选切分，而不是暴力尝试全部切法。

### 3.3 生成 DAG（切分候选图）

对句子每个位置 `i`：

1. 枚举从 `i` 出发的所有可命中词
2. 记录可到达的结束位置 `j`
3. 形成 `i -> j` 的有向边

整句得到一个 DAG：
- 节点：字符位置
- 边：一个候选词

本质上，DAG 压缩了所有候选切分路径。

### 3.4 动态规划找最大概率路径

在 DAG 上做动态规划（通常从后往前）：

- 利用词典词频近似词概率
- 计算路径总概率（常用对数概率求和）
- 选全局最优切分路径

这一步就是最大概率分词（MP）的核心。

### 3.5 HMM + Viterbi 识别未登录词（OOV）

对于词典不覆盖的片段，交给 HMM 处理：

1. 把字符序列映射为状态序列问题（常见 B/M/E/S）
2. 用 Viterbi 求最优状态路径
3. 按状态边界切出新词

这一步让分词器具备新词识别能力，不会完全依赖词典。

### 3.6 MixSegment 融合输出

混合模式结合：

- MP 的稳定性（词典概率路径）
- HMM 的泛化能力（OOV 识别）

你项目里的 `cut(sentence, true)` 是启用 HMM 的切分方式，可理解为“词典主导 + HMM 补充”。

### 3.7 在你项目里的完整链路

在 `PageLibPreprocessor` 中，分词只是前半段；后续还会：

1. 去停用词
2. 做 TF/DF 统计
3. 计算 TF-IDF
4. 做 L2 归一化
5. 写倒排索引

因此可把职责分成两层：
- CppJieba：决定“切成什么词”
- 检索模型：决定“这些词如何被加权和排序”

## 4. CppJieba 的“词”和 LLM 的“token”有什么关系

### 4.1 相同点

- 都是把原始字符串切成离散单元
- 都是后续计算的基础输入
- 切分策略都会影响最终效果

### 4.2 关键区别

1. 目标不同
- CppJieba：为检索与统计设计，偏“语言学词粒度”
- LLM Tokenizer：为神经网络建模设计，偏“子词/字节粒度”

2. 粒度不同
- CppJieba 常见结果是词语（如“搜索引擎”）
- LLM token 可能把同一词拆成多个子片段，甚至按字节编码

3. 稳定性不同
- CppJieba 对同一文本切分通常比较稳定可解释
- LLM token 受模型词表影响，跨模型不一定一致

4. 工程用途不同
- CppJieba 直接服务倒排索引、关键词统计、规则逻辑
- LLM token 主要服务“输入模型推理”

一句话：
- 可以把 CppJieba 的“词”理解为传统 IR 的 term
- 把 LLM 的 token 理解为神经模型可消费的离散编码单元
- 两者名字相似，但不是同一层抽象

## 5. “向量”在两套体系里分别指什么

### 5.1 当前项目里的向量（传统 IR）

本项目里虽然没有显式深度学习 embedding，但有典型“文档向量”思想：

- 每篇文档可看作一个 TF-IDF 稀疏向量
- 查询也可看作一个词项权重向量
- 通过权重累加/归一化实现相似度排序

这里的向量特征是：
- 高维稀疏
- 可解释性强（每一维对应词项）
- 便于离线构建、在线快速匹配

### 5.2 LLM/Embedding 的向量

大模型常说的向量通常是 dense embedding：

- 低维稠密（如几百到几千维）
- 每一维不直接对应可读词项
- 语义泛化能力强（同义、近义、上下文相关）

简化对比：
- TF-IDF 向量：关键词匹配强、可解释
- Embedding 向量：语义召回强、泛化好

## 6. 你可以怎么理解 token、term、向量这几个词

建议统一成三层：

1. 文本切分层
- term（传统分词结果）
- token（模型输入单元）

2. 特征表示层
- 稀疏词频向量（TF/TF-IDF）
- 稠密语义向量（embedding）

3. 检索计算层
- 倒排 + 打分（BM25/TF-IDF）
- 向量索引 + 相似度（cosine/inner product）

你当前项目主要在：
- term + TF-IDF + 倒排检索

大模型检索系统主要在：
- token + embedding + 向量检索

---

## 7. 两套方案不是替代关系，而是互补关系

在搜索工程里，常见是混合检索（Hybrid Retrieval）：

1. 先用关键词倒排召回（快、准、可控）
2. 再用语义向量补召回（解决同义改写）
3. 最后重排（可加规则或大模型）

因此 CppJieba 在你的项目里依然很有价值：

- 中文检索词项切分质量高
- 对关键词、实体词、短语查询非常有效
- 适合作为向量检索之前的高精度第一路召回

## 8. 对当前项目的一个务实建议（不改代码，只给方向）

如果后续想把“大模型 token/向量”概念渐进式接入，可以按最小风险路径：

1. 保留现有 CppJieba + 倒排索引主链路
2. 新增一条 embedding 召回链路（可离线构建向量库）
3. 在线阶段做双路召回融合
4. 用小规模评测集比较：
   - 精确关键词查询
   - 同义改写查询
   - 长尾自然语言查询

这样能在不破坏现有系统稳定性的前提下，引入语义能力。
